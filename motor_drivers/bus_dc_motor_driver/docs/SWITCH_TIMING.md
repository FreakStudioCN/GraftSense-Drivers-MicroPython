# 换向长尾拆开测：重复停机确实占了大头

这轮四路都上板跑了：同一套PI、160/200ms测速窗口、20ms节拍、±50%输出限幅，控制输出统一用批量写。只对比停机和STEP日志路径，避免把总线写法一起换掉。每组1秒零目标、6秒混合方向、6秒反向，最后主动走一次急停。400kHz和1MHz各测旧路径、全关帧、日志延后；最后各重复一次日志延后。

## 大头在哪

旧400k第一组最长37.890ms在1000ms起步：第一次硬件停机5.798ms，重复stop_all又9.453ms，参数切换1.439ms，STEP日志0.634ms，控制核心13.550ms，回读1.858ms，ADC1.394ms，遥测1.679ms，检查1.266ms，剩余调度/取数/计时等0.819ms。这里是同一拍分解，不能把每项各自最大值再拼起来。

本轮400k旧路径换向31.599ms，单帧18.690ms，延后STEP日志17.697ms，重复17.769ms。1MHz旧路径28.172ms，单帧16.933ms，延后15.812ms，重复结果见上表。去掉重复停机是主要收益；STEP日志单次约0.62～0.70ms，它不是几十毫秒的主因。延后指先存事件，电机关掉后再输出事件日志；100ms遥测仍保留，没有把所有日志都移走。

400k新路径仍出现20.186/20.822ms起步超预算，不能写成每拍都小于20ms。1MHz几组本轮均未超20ms，也只是短时台架结果；新的普通控制峰值主要落在core/检查等段，未给自然GC逐次打标签，不能直接归因于GC或PID算术。

上一轮38.141ms没有时间戳，无法追溯它到底是起步还是反向。本轮37.890ms明确在起步，31.599ms在反向，支持“状态切换里的重复停机很贵”，不冒充对旧峰值的精确定位。

## 急停和异常保留什么

八组都主动实测了一次急停：不等下一次flush，尝试8个通道逐个关闭，整拍约6.36～7.61ms，计入统计。每组100次全关帧预检、12次运行回读和结束全关回读通过，无通信异常。主机故障模拟另测全关写失败、回读不一致、软件禁用失败、急停首路失败及清理再失败：不启用反向，继续尝试关其他通道，保留首个异常。没有给真实硬件人为制造断线故障。

正常全关批量失败后不会假装成功，也不会继续反向；进入原有八通道尽力停机。I2C完全断线时软件无法保证物理关闭，这条测试验证的是尽力尝试和不再发出反向启动。
