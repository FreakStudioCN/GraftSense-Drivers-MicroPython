# 电机快一点更新，到底行不行？

这次不是只看电机能不能转，而是把四路曲线和板上的耗时一起量出来。PID还是0.15 / 0.60 / 0，只做了粗调。

## 先说结果

20ms能跑，但直接缩周期不等于更稳。跳过重复PWM写入后，四路更新平均从12.57ms降到9.12ms；再加80ms滚动测速，更新约10.21ms，反馈抖动有所下降。正式库的默认周期和硬件写入行为没有改，优化只放在独立试验入口。

## 串口、录屏和下一步

PC请求波特率921600。COM8是USB JTAG串口，设置这个数不代表物理USB一定快8倍。真正有效的是把长CSV改成紧凑报文并控制在约10Hz：单次发送平均从约13ms降到约1.7ms。

第一次连续长CSV试跑中止，原始日志保留。短窗口偶尔读到零不能立刻当作堵转；现在从目标启动时计时，连续2.5秒计数没变化且驱动输出超过25%才停机。

每圈260个计数，100/30/20ms单个计数分别对应约2.31/7.69/11.54RPM。短周期测速跳动是可预期的；80ms窗口有助于减轻跳动，也会带来反馈延迟。建议先用30ms作下一轮调参起点，再比较20ms加明确测速窗口；先把低速、启停和带载调好，再讨论小车是否丝滑。重复写缓存仅用于独占PCA实验，不直接作为共享总线通用策略。

live-plot-edited.mp4为真实实时图窗采集的精简回放，不是事后模拟曲线；播放器时长不用于计量，时间看图中设备横轴。第5档用80ms窗口，录制图例中raw字样已在成片附加说明中纠正。两次中止记录与最终完整五档记录分开保存。

## 怎么重跑

安装：`pip install matplotlib numpy pillow pyserial mpremote`

`python motor_drivers/bus_dc_motor_driver/tests/pc_live_plot.py --port COM8 --baud 921600 --run --seconds 10 --out 新的输出目录`

这会备份并上传当前包到板上/lib，运行有限时长测试，退出时关闭电机。默认不改设备main.py。按需改端口。输出CSV、JSON、串口日志、实时曲线录屏和截图。关图窗会请求停止；试验包括80ms窗口这一档，界面会明示。
