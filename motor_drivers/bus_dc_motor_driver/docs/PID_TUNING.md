# 四路电机 PID 参数整定指南

这份指南说明怎么调、怎么看结果，以及这套台架目前调到了什么程度。具体实测曲线见[细调记录](TUNING.md)，控制周期与 GC 等耗时见[实时性评估](REALTIME.md)。

## 1. 先弄清楚四个量

| 量 | 在本库里是什么意思 | 调整时主要看什么 |
|---|---|---|
| P | 当前转速误差乘以 Kp，直接影响输出 | 太小反应慢，太大可能来回振荡 |
| I | 把误差按实际 dt 累加，再乘 Ki | 用来消除长期偏差；太强会积累过多，起步冲高、恢复慢 |
| D | 误差变化率乘以 Kd | 可能帮助抑制变化，也会放大测速跳动；本次保持为 0 |
| 测速窗口 | 用多长时间内的编码器计数估算转速 | 窗口短，读数更容易跳；窗口长，反馈有延迟 |

本库 PID 的计算顺序是：

```text
error = target_rpm - feedback_rpm
integral = clamp(integral + error * dt, integral_min, integral_max)
output = clamp(Kp * error + Ki * integral
               + Kd * (error - last_error) / dt,
               output_min, output_max)
```

`dt` 单位为秒，来自实际更新间隔。电机应用里输出是带方向的 PWM 百分比，和旧接口的 `1900～4095` 原始数值不是同一单位。参数也不能直接套用到使用不同公式或单位的其他 PID 库。

积分限幅限制的是 `integral` 状态，不是最终 I 项输出。例如 Ki=0.2、积分限幅为 ±150，I 项最多贡献 ±30% PWM。当前实现有积分状态限幅，但没有根据输出饱和情况暂停积分；不能把它当作完整的条件积分抗饱和方案。

## 2. 控制周期和测速窗口分开调

20 ms 控制周期表示大约每 20 ms 计算一次并更新输出，不代表每 20 ms 就能得到很精细的低速测速。

本次编码器按 260 个计数/输出轴圈换算。固定窗口内多一个计数，对读数的影响约为：

| 测速窗口 | 一个计数对应的转速差 |
|---|---:|
| 20 ms | 11.54 RPM |
| 100 ms | 2.31 RPM |
| 160 ms | 1.44 RPM |
| 200 ms | 1.15 RPM |

因此，低速时直接用 20 ms 的计数差做反馈，曲线容易跳。当前独立试验入口用最近若干次计数和实际 dt 的总和计算滚动转速，并把这个窗口反馈送给 PID，既影响显示，也影响控制。

从零整定时，先固定周期和统一的测速窗口，方便比较参数；不要一边调 P/I，一边不断改变窗口。四路并不必须使用不同窗口。本次保存的是分路实测配置，没有证明它优于所有统一窗口方案。窗口越长也不一定越好，需要一起观察响应速度。

## 3. 开始前固定测试条件

1. 确认电机编号、正反方向、每圈计数和电压换算正确，先让电机能自由转动。
2. 固定供电、PWM 频率、控制周期、测速窗口和输出限幅。先用同一组低速目标做比较。
3. 一次只让一个控制器管理同一组 PCA 通道。安装库本身不会自动启动 PID，设置目标后还要显式启动。
4. 每次测试前停止输出、清理旧控制器资源，避免旧积分或回调影响下一轮。
5. 记录代码版本、各路参数、窗口、限幅、供电、目标、反馈和异常。输出饱和或保护停机的记录也要保留。

本次台架使用 ESP32-C3、MicroPython v1.29.0、PCA9685 地址 0x4F，PWM 为 1000 Hz，控制周期为 20 ms。具体引脚见 [board_setup.py](../examples/board_setup.py)。换电机、减速比、供电或负载后，需要重新验证。

## 4. 按这个顺序调

### 4.1 先确认死区，再调 P

先了解电机在正反方向大约需要多少输出才开始转。电机不动时，先看输出是否还没越过起转区、是否已经限幅，不要只看到误差大就一直增加增益。

从零调时可以先让 I、D 为 0，用较小的 P 做短时测试，再小步增加 P。目标是让电机有反应、误差下降，又不反复冲过目标。只有 P 时留有稳态偏差很常见；这一步不是为了把偏差彻底调没。

如果准备使用起步补偿，先固定补偿方案和数值；否则它会和增益变化混在一起。本次没有靠寻找持续振荡的临界增益来整定。

### 4.2 用 I 把长期偏差补回来

P 大致合适后，逐步增加 I，观察目标附近的平均误差是否减小。每次只改一项，改变后让该轮完整跑完，再比较同样长度的后段。

- 平均误差一直存在、输出还没有限幅：可以小步增加 I。
- 起步冲高、围绕目标缓慢摆动：尝试减小 I，并检查起步补偿和积分状态。
- 一直顶着输出限幅仍达不到目标：先查供电、负载、目标是否可达，别继续堆 I。

减小 Ki 时也要复核积分状态限幅，避免 I 项最大输出变得太小，根本无法维持目标转速。

### 4.3 暂时不用 D，也可以先把 PI 调好

这次四路都使用 D=0。当前 D 根据误差差分计算，目标突变和测速跳动都可能使 D 项产生较大的瞬时输出。只有确定需要抑制哪一种动态、且反馈噪声可控时，再小步试 D；不要把 D 当作通用的“平滑开关”。

### 4.4 先单路，再四路，再上车

每个候选至少对比正转、反转和低速；四路一起运行时，再测混合方向、同时变速和重复启动。不能只保留表现最好的一次。

空载台架基本满意后，再验证落地负载、转向、真实遥控链路和长时间运行。小车是否跟手，要看命令到输出延迟、起步/换向响应和周期长尾，不能只看最后几秒转速准不准。

## 5. 当前保存的台架配置

下表是实测起点，不是通用默认参数。

| 电机 | Kp | Ki | Kd | 测速窗口 |
|---|---:|---:|---:|---:|
| M1 | 0.25 | 0.30 | 0 | 160 ms |
| M2 | 0.25 | 0.25 | 0 | 160 ms |
| M3 | 0.30 | 0.25 | 0 | 200 ms |
| M4 | 0.15 | 0.20 | 0 | 200 ms |

共同设置：控制周期 20 ms、输出限幅 ±50%、积分状态限幅 ±150，启动时给 I 项预置带方向的 8% PWM 贡献。

起步预置的换算为 `integral = signed(8) / Ki`，再按积分状态上下限截断；Ki=0 时不预置。它不是每周期额外加 8%，也不是把积分状态直接设成 8。停机仍会禁用 PID、清除动态状态。该预置只在整定入口启动时调用。

这组配置在五组正反转/低速复测中，20 个电机与工况组合满足后段平均误差、波动的基础标准，最大平均误差约 0.86 RPM。但仍有一次 M1 起步观测超调为 38.57%，首次达到目标 90% 约需 1.6～3.5 秒。它是“台架匀速基本可用”，还不是“整车已经丝滑”。

配置文件：[recommended.json](tuning/recommended.json)。实际执行入口：[tuning_profile.py](../examples/tuning_profile.py)。通用运行库的默认参数没有被这组台架配置覆盖。

## 6. 用现有脚本重跑

在仓库根目录的 PC 终端执行：

```powershell
pip install matplotlib numpy pillow pyserial mpremote
python motor_drivers/bus_dc_motor_driver/tests/pc_live_plot.py --profile tuning_profile --port COM8 --baud 921600 --run --seconds 15 --out pid-tune-01
```

输出目录必须是新目录。明确加 `--run` 后，脚本才会备份并上传库、倒计时并运行电机，不修改设备 `main.py`。COM8 是本次板子的 USB 串口，换板要改端口；921600 是主机请求值，不能据此认定 USB 链路一定同比提速。

调整时修改 `examples/tuning_profile.py` 中：

- `MOTOR_PRESETS`：按 M1～M4 排列的 `(Kp, Ki, Kd, window_ms)`。
- `STARTUP_I_PERCENT`：起步 I 项预置贡献，当前为 8；需要排除起步补偿影响时显式设为 0。
- `VALIDATION_TARGETS`：各阶段的四路目标，当前入口限制在 −60～60 RPM。

只修改 `PROFILES` 不会覆盖默认的 `MOTOR_PRESETS`。如果通过设备 Python 接口做统一参数扫描，应显式传 `per_motor=None`，并同时提供与阶段数量对应的 `target_profiles`。窗口目前要求为 20～300 ms 且能被 20 整除，单段运动时长限制为 5～20 秒。

先保留默认完整上传；`--reuse` 仅用于已确认板上运行库与当前代码一致的情况。脚本会保存 `samples.csv`、`serial.log`、`summary.json`、实时图窗视频与截图。图中要明确反馈窗口，不能把窗口测速标作原始 20 ms 测速。

## 7. 看哪些指标，怎么算

| 指标 | 本次的定义 | 容易误读的地方 |
|---|---|---|
| 平均误差 | 后段平均反馈减目标 | 只说明长期偏差，不说明起步快 |
| 波动 | 后段反馈的标准差 | 测速窗口改变后，要连同窗口一起比较 |
| 观测超调 | 超过目标方向的最大反馈，除以从零起步的目标绝对值 | 反转按负方向计算；10 Hz 遥测可能漏掉窄峰 |
| 严格稳态时间 | 反馈进入目标 ±5% 后，持续到记录结束且至少保持 1 秒 | 未达到就记未达到，不拿最后均值替代 |
| 达到目标90%的时间 | 从第一条带新目标的遥测到首次越过90% | 存在约一个遥测周期的起点误差，也不等于稳态时间 |
| 实时性 | 全周期 P95/P99、最大值、超预算次数、命令到输出延迟 | 平均周期20ms不代表每周期都准时 |

本次“基本满足”另外使用以下后段标准，不把它称作严格稳态通过：

```text
取每组最后5秒：
abs(平均反馈 - 目标) <= max(abs(目标) * 5%, 2 RPM)
反馈标准差          <= max(abs(目标) * 10%, 3 RPM)
启动超调尽量压到25%以内，超出的仍单独记录。
```

这些是本项目的空载台架判断值，不是行业标准。PC 脚本 `summary.json` 的 `mean_tail_rpm/std_tail_rpm` 默认统计最后 **2 秒**；本次基础验收另从 CSV 计算最后 **5 秒**，结果保存在 [basic-acceptance.json](tuning/basic-acceptance.json)。二者不能直接混用。

## 8. 常见现象怎么查

| 现象 | 优先检查 |
|---|---|
| 低速不动，随后突然冲高 | 起转死区、积分积累、预置贡献、负载；保留无反馈保护 |
| 在目标两侧快速摆动 | P 是否过大、反馈延迟/跳动、控制周期是否抖动 |
| 慢慢冲高再回落，循环往复 | I 是否过强，窗口是否过长，是否发生输出饱和 |
| 平均转速准，但读数仍跳 | 计数分辨率、窗口和机械波动；同时看PWM变化，不能只改显示曲线 |
| 单路好，四路一起变差 | 全周期预算、I2C写入、GC、日志和供电；别只重调增益 |
| 正转好，反转差 | 正反向死区和负载差异，分方向复测 |
| 换一次参数后结果不可重复 | 停机/清积分、资源释放、供电和温度、测试版本、目标与统计区间是否一致 |

计时工具已经包含微秒装饰器与直方图，见 [timing_audit.py](../examples/timing_audit.py) 和[实时性评估](REALTIME.md)。装饰器测到的是包含中断、GC和包装开销的墙钟时间；I2C、PID是整周期的子项，不能再与总耗时重复相加。

## 9. 每轮至少留这些记录

代码提交号、板卡/固件、供电、负载、每圈计数、控制周期、各路窗口、P/I/D、积分和输出限幅、起步预置、目标序列、CSV、统计区间、超调/响应时间、周期分位数，以及保护停机原因。

记录“改了什么、好在哪、坏在哪、下一轮只改什么”。结果已经基本可用时，可以保留明确的剩余问题收敛；不要把一次漂亮曲线当成所有方向、负载和供电条件都已调好。

### 一键复算末五秒结果

在仓库根目录运行：

```powershell
python motor_drivers/bus_dc_motor_driver/tests/recompute_acceptance.py --csv motor_drivers/bus_dc_motor_driver/docs/tuning/samples.csv --check motor_drivers/bus_dc_motor_driver/docs/tuning/basic-acceptance.json
```

`--check` 会逐项比较均值、标准差、观测超调及通过标志，不一致时失败退出。换成自己的CSV并使用 `--output 结果.json` 可保存新结果；不足约五秒或后段目标变化的记录会报错，不会凑出一次通过。
